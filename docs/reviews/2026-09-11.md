## 変更内容

### `firewall.pair` → `firewall.cluster_firewall_pairs` への再設計

**変更理由:**
初期実装の `pair: { primary: String, secondary: String }` は単純なノード名ペアのみを保持する
設計だったが、HA クラスタのインタフェース構成情報 (ファブリック/コントロールリンク) も
扱えるようにする必要が生じた。

**変更後の構造:**
`cluster_firewall_pairs: Array` に変更し、各ペアが `primary`/`secondary` ノードオブジェクトを持つ。
各ノードは `atypical_interfaces` を持ち、インタフェースごとに `role` (`'fabric'` または `'control'`)
と、`role == 'fabric'` のときのみ `fabric_options` を保持する。

## 設計上の判断

**`fabric_options` の条件出力:**
`role == 'control'` のインタフェースには `fabric-options` キーが不要なため、
`MddoL3FirewallAtypicalInterface#to_data` (Topology 層) と `topo_data` (DSL 層) で
`role == 'fabric'` のときのみ `fabric-options` を出力するよう制御した。

**`empty?` の判定基準:**
`MddoL3Firewall#empty?` は `cluster_firewall_pairs.empty?` のみで判定する。
ゾーンやポリシーが存在しても、クラスタペア情報がなければ FW ノードとして扱わない設計。
ユーザー確認済み。
